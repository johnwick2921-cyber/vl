## What changed

### S1 — kernel (`kernel/mentor/swing4h.go`)
- `SwingState` gains `Pending *swingPosition` (the resting stop order) beside `Pos *swingPosition` (the FILLED leg); `swingPosition` gains `ExpiryMs`.
- `openPosition` now records the **Pending** order (with the current-4h-candle expiry), never the filled position.
- The position opens only when a closed bar **trades through its own entry** (`fillsSwingEntry`), and clears on:
  - **expiry** — `now >= Pending.ExpiryMs` (close of the current 4h candle, the same `swingExpiry(now)` the intent carries);
  - **cancel** — the through-close `CancelArm` now names the pending's ArmID and clears it.
- `manageSwingPosition` runs AFTER the bar walk, so a fill that happened THIS tick is managed against the fill bar's close (not one bar late).

### S1 — trader (`trader/mentor_actions.go`)
- `mentorSwingFill` resolves the arm's ledger row; `mentorMoveStopBE` and `mentorClosePosition` now require the arm to be **FILLED**.
- The close sends the swing leg's **own fill quantity** (`FillQuantity`, default 1), never a side-wide `0`.
- Unfilled / unattributed → **refuse + log**, with named counters (`move_be_refused_not_filled`, `close_refused_not_filled`, `swing_fill_row_gone`, `swing_fill_no_ledger`).

### S2 — seed + drop guard (`kernel/mentor/seed.go`, `kernel/mentor/eval.go`)
- `Seed` stamps `Swing.LastBarTime` at the **newest closed 5m bar**, so the first tick walks only NEW bars.
- `runSwing` drops any swing entry whose reference candle (ArmID timestamp) is older than the newest closed 5m bar (`dropStaleSwingIntents`) — second line of defence even if the watermark were missing.
