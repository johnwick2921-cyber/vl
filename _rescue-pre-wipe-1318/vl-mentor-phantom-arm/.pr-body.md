## Summary

- Problem (MENTOR-ARM-DIVERGENCE, accepted 2026-10-08): when the trader refused a mentor placement as a DEAD setup, it never told the evaluator. The evaluator kept a phantom arm — `isb_arm_active` suppressed the next same-side setup for minutes after a flat close, and follow-up `ExtendArm`/`CancelArm`/`MoveStopBE` intents kept firing for an order that was never authored (even "+1R → stop to break-even" on a swing arm that was never placed). The empty `ArmID ""` cancel came from `SwingTick`'s close-through-line branch emitting a cancel with nothing resting.
- What changed (after CTO fold — ONE guard, not nine):
  - `kernel/mentor`: `Evaluator.DropArm(armID)` — deletes the ISB arm, else clears `Swing.Pending` when its `ArmID` matches. Never touches a FILLED `Swing.Pos`; no-op on nil/empty evaluator or id.
  - `trader`: `mentorDropEvalArm` (the ONE guard already run by `mentorDispatchEntry`'s defer on every refusal, X-07) now drops the evaluator's own arm too — `State.Limits.DropArm` (G1/G2 pend) + `Evaluator.DropArm` (ISB / swing Pending). The defer skips an arm already in `mentorLiveArmFor` (registered = the row was authored), so a live arm is never dropped. No scattered per-gate calls.
  - `kernel/mentor/swing4h.go`: the close-through-line cancel only emits `CancelArm` when `Swing.Pending != nil` — no more `ArmID ""` intents.
- What did NOT change: the #449 armed-pass stale refusal (`armed_executor.go` / `mentorOnlyPlacementPass`) keeps the row armed and retries when fresh — untouched; exits/protection never gated; a FILLED swing position (`Swing.Pos`) is never dropped. Every refusal path — `mentorRuleGate`, `mentorSizeFor` error, `MENTOR_PLACE` off, the placement gates, the N10 stale-intent refusal, sources-missing, no-ledger / upsert-failed / authored-no-row, bad side — now funnels through the same defer.
